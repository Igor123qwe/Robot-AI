# Голосовой пайплайн (v1)

```
микрофон → webrtcvad → faster-whisper ─┬─ правила ──────────┐
                                       │  (стоп, вперёд…)   │
                                       └─ модель (tool use) ┴→ Piper → динамик
                                                    ↓
                                          rosbridge → /cmd_vel
```

## Два уровня разбора

Простые команды разбираются регулярками в `intents.py` — мгновенно, бесплатно
и предсказуемо. «Стоп» или «вперёд на метр» не требуют языковой модели, а вот
цена ошибки высока: «влево» вместо «вправо» означает, что робот поехал не туда.

Правила намеренно строгие: совпало точно — выполняем, во всём остальном
отдаём модели. Ошибиться в сторону «спросил умного» дешевле.

Что разбирается без модели:

| Фраза | Действие |
|---|---|
| стоп, стой, притормози, прекрати, отставить, замри | остановиться |
| вперёд / назад / влево / вправо, «на 1.5 метра», «на 30 см», «полметра», «чуть-чуть» | ехать |
| развернись направо, на 90 градусов, кругом | разворот |
| сколько заряда | батарея |
| задай / установи / запусти / включи / поставь таймер на 10 минут, «на 1 час 30 минут», «таймер лапша на 9 минут» | таймер |
| что с таймерами, сколько осталось у таймера, какие таймеры | список |
| отмени таймер лапша, сбрось все таймеры | снять таймеры |

Всё прочее — «поезжай к холодильнику», «поставь таймер когда закипит чайник»,
«забудь», любой разговор — уходит модели, у которой те же инструменты.

Формулировки для таймеров, статуса и отмены взяты не из головы, а из русских
интентов Home Assistant ([OHF-Voice/intents](https://github.com/OHF-Voice/intents),
каталог `sentences/ru`) — их писали и вычитывали носители языка.

### Как пополнять

Лучший источник — собственный лог: это выборка под конкретного человека, а не
усреднённый корпус. Строки, где правила не сработали, помечены явно:

```
journalctl -u robot-voice | grep -B1 "правилами не разобрал"
```

Если в выдаче регулярно попадаются команды (а не разговор) — их формулировки
стоит добавить в `intents.py`. Если начнут мелькать далёкие перефразировки,
которые регуляркой не поймать, — тогда имеет смысл второй слой, семантический
роутер на эмбеддингах.

## Что уже есть

- **Захват звука** из двух источников: телефон с IP Webcam (`/audio.wav`) или
  локальный микрофон RDK X5. Переключается переменной `ROBOT_AUDIO_SOURCE`.
- **Нарезка на фразы** по webrtcvad: начало речи → 700 мс тишины → фраза готова.
- **Слово пробуждения** — проверка по тексту («робот, …»). openWakeWord не тянем,
  пока микрофон на телефоне: задержка Wi-Fi всё равно не даёт нормального
  always-on режима.
- **Claude с инструментами**: ездить, разворачиваться, стоять, проверять
  батарею, ставить и отменять таймеры. Ответ идёт потоком, синтез начинается
  с первого законченного предложения — робот не молчит, пока модель думает.
- **Синтез** Piper. Куда выводить — решает `ROBOT_AUDIO_OUT`:
  - `browser` (сейчас) — реплика собирается в WAV и уходит в веб-сервер робота,
    играет её браузер с открытым пультом. Своего динамика у робота ещё нет,
    а IP Webcam умеет только отдавать звук, но не принимать.
  - `local` (когда приедет SOTAMIA) — один процесс Piper на реплику, сырой звук
    прямо в `aplay`, потоком по предложениям.

  Разница в задержке: в режиме `browser` синтез идёт целиком на реплику, иначе
  Piper пришлось бы поднимать на каждое предложение. Ответы у нас в одно-два
  предложения, так что это терпимо.

## Чего нет и почему

**Barge-in (перебить робота голосом) не работает.** Пока микрофон на телефоне,
задержка по Wi-Fi плавает, и программный AEC на такое не способен: робот будет
слышать сам себя и реагировать на собственную речь. Поэтому режим строго
половинного дуплекса — пока говорит, микрофон заглушён.

Появится вместе с ReSpeaker Lite (XMOS XU-316, аппаратный AEC). Тогда сюда
приедут Silero VAD и переезд на Pipecat/LiveKit Agents.

## Установка

```
bash ~/Robot-AI/scripts/setup_voice.sh
```

Скрипт создаёт venv, ставит зависимости, качает голос Piper и включает сервис.

Лог:

```
journalctl -u robot-voice -f
```

## Запуск вручную (для отладки)

```
cd ~/Robot-AI/voice && set -a && . ~/.robot-ai.env && set +a && .venv/bin/python -m robot_voice
```

## Настройки

Всё в `~/.robot-ai.env`, см. `.env.example`. Что чаще всего крутить:

| Переменная | Смысл |
|---|---|
| `ROBOT_EFFORT` | `low` — быстрые ответы, `high` — умнее и медленнее |
| `ROBOT_WHISPER_MODEL` | `tiny` быстрее, `base` точнее, `small` — уже тяжело для A55 |
| `ROBOT_AUDIO_SOURCE` | микрофон: `phone` или `local` |
| `ROBOT_AUDIO_OUT` | динамик: `browser` или `local` |

Порог тишины, агрессивность VAD и слова пробуждения — в `robot_voice/config.py`.

## Добавить свой инструмент

В `robot_voice/tools.py`, внутри `build_tools`:

```python
@beta_tool
def включи_свет(комната: str) -> str:
    """Включает свет в комнате.

    Args:
        комната: Название комнаты.
    """
    ...
    return "Готово."
```

и дописать функцию в `return [...]`. Схема для модели собирается из сигнатуры и
docstring'а — описания аргументов пишутся для модели, а не для человека.

## Куда ходит за ответом

Умеет и напрямую в Anthropic, и через сторонний роутер, лишь бы тот понимал
протокол Anthropic (`/v1/messages`). Проверяется одним запросом:

```
curl -s -o /dev/null -w '%{http_code}\n' https://РОУТЕР/api/v1/messages -H "x-api-key: КЛЮЧ" -H "anthropic-version: 2023-06-01" -H "content-type: application/json" -d '{"model":"МОДЕЛЬ","max_tokens":16,"messages":[{"role":"user","content":"привет"}]}'
```

`200` — годится, ставим `ROBOT_API_BASE`. Через роутер **обязательно очистить
`ROBOT_EFFORT`**: этот параметр за пределами Anthropic не знают, и запрос
отвалится с 400.

## Заметки по модели

- Цикл «модель → инструмент → модель» написан руками, а не отдан `tool_runner`
  из SDK. Тот живёт на beta-эндпоинте, а прокси такое обычно не пропускают.
  Обычный `/v1/messages` работает везде одинаково.
- Схемы инструментов описаны явно, по той же причине — автогенерация из
  сигнатур завязана на beta.
- Напрямую с `claude-opus-5` размышления (thinking) включены по умолчанию, и
  отключать их не стоит: без них модель иногда пишет вызов инструмента обычным
  текстом, и вызов молча не выполняется. Скорость регулируется через
  `ROBOT_EFFORT=low`.
- Для голоса соблазнительно взять модель полегче, но инструменты здесь
  управляют железом: ошибка вызова означает «поехал не туда». Скорость стоит
  выигрывать через `effort` и краткость промпта, а не через сильно более
  слабую модель.
- За один ход разрешено не больше шести обращений к инструментам — предохранитель
  от зацикливания.
