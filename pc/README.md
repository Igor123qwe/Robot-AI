# Мозг на домашнем ПК

У RDK X5 нет видеокарты и не будет. Языковую модель он не потянет вовсе, а
Whisper тянет через силу: самую лёгкую версию и втрое медленнее звука,
половину слов перевирая. Дома при этом стоит компьютер с видеокартой,
включённый ровно тогда, когда с роботом разговаривают.

Поэтому у робота уши, рот и колёса, а тяжёлое считает ПК. Так же устроены
Алиса и Google — разница лишь в том, что их «компьютер» стоит в чужом
дата-центре.

**Робот работает только в паре с ПК** (решение хозяина, 17 октября 2026).
Распознавание, разговор, голос, зрение и лицо на экране — всё здесь. Своего
Whisper, своего Piper, облачного запаса и своего лица у робота больше нет.
ПК выключен, `kuzya_pc.py` не запущен или не поднята Ollama — робот молчит:
не говорит «ПК не отвечает, я работаю сам», не объявляет «нет сети», а на
его экране только часы, строка состояния и карточки. От ПК не зависит
только остановка: «Кузя, стоп», кнопка СТОП и сторож мёртвой руки работают
на самом роботе.

## Что это даёт

| | раньше на роботе | на ПК |
|---|---|---|
| распознать фразу в 2 секунды | 3.7 с, модель `base` | ~0.3 с, модель `small` и крупнее |
| ответить | 3–10 с через облако, платно | 1–2 с, бесплатно |

Левый столбец — история: так было, пока у робота был свой запасной путь.
Теперь его нет вовсе.

## Установка

Нужны две вещи: **Ollama** запускает модель, `kuzya_pc.py` переводит наш
протокол в её и заодно распознаёт речь.

```
winget install --source winget Ollama.Ollama
ollama pull qwen3:4b-instruct-2507-q4_K_M
pip install faster-whisper
```

Модели тяжёлые — если системный диск невелик, уведите их заранее:

```
setx OLLAMA_MODELS "F:\ollama\models"
```

И три переменные для скорости — один раз:

```
setx OLLAMA_FLASH_ATTENTION 1
setx OLLAMA_KV_CACHE_TYPE q8_0
setx OLLAMA_NUM_PARALLEL 1
```

Быстрое внимание, кэш вдвое компактнее и один разговор за раз (на 6 ГБ
несколько кэшей не помещаются, а некоторые сборки Ollama заводят их сами).
Со сжатым кэшем мост сам просит окно побольше — 10240 токенов вместо 8192, —
а места это занимает меньше, чем 8192 без сжатия. `start.cmd` напоминает об
этих строках, пока их нет.

Переменные действуют только на новые окна: закройте командную строку и
откройте заново, а Ollama выйдите из трея и запустите снова — её `set` из
окна `start.cmd` не достаёт, она живёт в трее своим окружением.

## Запуск

```
python kuzya_pc.py --model qwen3:4b-instruct-2507-q4_K_M --whisper small
```

`start.cmd` делает то же двойным щелчком и сам скачивает модель, если её
ещё нет.

Окно должно остаться открытым — это и есть мозг. Проверить из браузера:
`http://127.0.0.1:4000/health`.

Ollama тоже должна работать — висеть в трее. Если в окне `kuzya_pc.py` при
запуске есть строка «Ollama по адресу http://127.0.0.1:11434 не
отвечает» — запустите Ollama: без неё разговаривать не с кем, и робот
будет молчать.

Пока распознавание на ПК прогревается после запуска, `/stt` сразу отвечает
503 «прогреваюсь» — робот эту фразу молча пропускает и следующую несёт
сразу, без пауз и без объявлений.

Порт нужно открыть, иначе робот не достучится. Один раз, от администратора:

```
netsh advfirewall firewall add rule name="kuzya" dir=in action=allow protocol=TCP localport=4000
```

## Лицо робота — шар из точек

Лицо Кузи — живой шар из точек. Рисует его этот ПК, на видеокарте
(`pc/avatar/orb.html`): около десяти тысяч точек на пружинах, свечение,
превращения в четырнадцать фигур, свои сюжеты в покое (рой, светлячки,
созвездие, волны цвета) — и шлёт роботу потоком кадров. Нужен `pip
install playwright` и Edge или Chrome. Что робот видит прямо сейчас:
`http://127.0.0.1:4000/avatar/frame.jpg`, сам шар в браузере —
`http://127.0.0.1:4000/avatar/orb.html`.

Без Playwright лица на экране робота не будет — `kuzya_pc.py` скажет об
этом в окне при запуске. Своего шара у робота нет (`face/orb.py` удалён 17
октября 2026): ПК выключен — на экране робота только тёмный фон, часы,
строка состояния и карточки, и ни слова о том, что ПК пропал. Служебных
надписей страницы («нет связи», «пробую снова») робот тоже не видит:
съёмка открывает шар с `?робот=1`, и они уходят только в консоль браузера,
а оттуда — в окно `kuzya_pc.py`. Как шар себя ведёт и где стоит на экране
— `face/orb_rules.py`, общий с роботом: по его `РАСКЛАДКЕ` робот понимает,
куда ткнули пальцем, и шлёт касание сюда.

Персонажей на экране больше нет: ни домовёнка, ни Live2D-Марка. Live2D и 3D
остались для того, кто вернёт их нарочно: `{"движок": "live2d"}` или
`{"движок": "3d"}` в `pc/avatar/config.local.json` — всё в
`pc/avatar/README.md`.

## Распознавание получше

По умолчанию речь разбирает Whisper — русское дообучение `large-v3-turbo`.
Рядом лежит **GigaAM** от Сбера: его учили на семистах тысячах часов русской
речи против доли русского у Whisper, и на коротких редких словах — вроде имени
робота — разница заметна.

```
git clone https://github.com/salute-developers/GigaAM.git
cd GigaAM && pip install -e .[torch]
```

**Ставьте это в отдельное окружение на большом диске.** Колесо `torch` с
поддержкой видеокарты — 2.6 ГБ в архиве и около шести на диске, плюс столько
же временно. На системном диске столько находится не всегда, а обрывается
установка уже ПОСЛЕ удаления прежней сборки — робот остаётся без
распознавания вовсе. Разбирать это в час ночи неприятно.

```
mkdir F:\tmp & mkdir F:\pip-cache
set TMP=F:\tmp& set TEMP=F:\tmp& set PIP_CACHE_DIR=F:\pip-cache
python -m venv F:\robot-venv
F:\robot-venv\Scripts\activate
```

Три переменные обязательны: pip распаковывает колесо во временную папку, а
она по умолчанию на системном диске — то есть само окружение уедет на F, а
место кончится всё равно.

Если включён VPN, pip откажется словами **«Missing dependencies for SOCKS
support»**. Клиент прописывает в систему прокси схемы SOCKS, а pip без
отдельной библиотеки такую схему не понимает — и не скачивает вообще ничего,
даже саму эту библиотеку. Прокси для установки не нужен, снимаем его на одно
окно:

```
set HTTP_PROXY=& set HTTPS_PROXY=& set ALL_PROXY=
set http_proxy=& set https_proxy=& set all_proxy=
```

Те же грабли уже описаны в коде (`_proxy_trouble` в `kuzya_pc.py`): там VPN
мешал скачать модель распознавания, и обход сделан прямо в программе. Здесь
приходится руками — pip чужих подсказок не принимает.

Дальше ставьте torch ПЕРВЫМ, до GigaAM:

```
pip install torch torchaudio --index-url https://download.pytorch.org/whl/cu126 --no-cache-dir
pip install faster-whisper numpy speechbrain
git clone https://github.com/salute-developers/GigaAM.git
cd GigaAM && pip install -e .
```

Обратите внимание: `pip install -e .` **без** `[torch]`. Именно этот довесок
и тянет сборку для процессора — если позвать его после, он молча заменит уже
поставленную и всё вернётся к началу.

`start.cmd` найдёт это окружение сам. Лежит оно в другом месте — задайте
`ROBOT_VENV`.

**Проверьте, видит ли torch видеокарту.** Это не
формальность: на Windows `pip install torch` тянет с PyPI сборку ДЛЯ
ПРОЦЕССОРА, и распознавание молча уезжает считаться на нём. Робот при этом
работает — просто вшестеро медленнее, и в журнале мелькает одно
предупреждение при запуске, которое легко пропустить.

```
python -c "import torch; print(torch.cuda.is_available(), torch.version.cuda)"
```

Ответ `False None` означает, что видеокарта простаивает, а распознавание,
синтез и узнавание голоса дерутся за ядра процессора — на живом роботе это
давало разброс от 0.7 до 5.4 секунды на одной и той же фразе. Лечится
установкой сборки под CUDA (номер после `cu` — под вашу версию драйвера,
смотреть в `nvidia-smi`):

```
pip uninstall -y torch torchaudio
pip install torch torchaudio --index-url https://download.pytorch.org/whl/cu126
```

Должно ответить `True 12.6`.

Нужен ffmpeg в PATH. Дальше запускать с флагом:

```
python kuzya_pc.py --model qwen3:4b-instruct-2507-q4_K_M --stt gigaam --port 4000
```

**Чем платим.** GigaAM не отдаёт уверенность распознавания. У Whisper есть
число, по которому робот решает, можно ли по услышанному ехать: невнятная
команда отбрасывается с «расслышал слишком плохо». С GigaAM этой защиты нет —
остаются только текстовые сетки и узнавание по голосу. Поэтому он не включён
по умолчанию: выбор осознанный, а не «поставили новее — значит лучше».

Если GigaAM не поднимется, робот не оглохнет: возьмётся Whisper, о чём будет
сказано в первых строках запуска.

## Настройка робота

Узнайте адрес ПК (`ipconfig`, строка IPv4) и допишите в `~/.robot-ai.env`
одну строку:

```
ROBOT_PC_URL=http://192.168.0.X:4000
```

Она включает сразу всё: распознавание, разговор, голос, зрение и лицо.
Дальше:

```
sudo systemctl restart robot-voice robot-face
```

В журнале голоса должно появиться «распознавание на ПК: …» и «собеседник —
только ПК: …», а после первого вопроса — «отвечал ПК (…)».

Проверить связь до настройки можно прямо с робота:

```
curl -s http://192.168.0.X:4000/health
```

## Выбор моделей

Сначала узнайте, сколько у вас видеопамяти на самом деле — на глаз тут
ошибаются постоянно, а от этого зависит всё:

```
nvidia-smi --query-gpu=name,memory.total --format=csv
```

Считать надо не «сколько на карте», а «сколько останется модели»: на той же
карте живёт распознавание речи. GigaAM — это несколько сотен мегабайт, Whisper
`large-v3-turbo` — около полутора гигабайт. Плюс KV-кэш под контекст. Рабочее
правило: **файл модели должен быть примерно на 2 ГБ меньше видеопамяти.**

| видеопамять | модель | файл | ответ |
|---|---|---|---|
| 6 ГБ | `qwen3.5:4b` (или `gemma4:e4b`) | ~2.5 ГБ | ~1 с |
| 8 ГБ | `qwen3.5:4b` свободно, `qwen3.5:9b` впритык | 2.5 / 5.5 ГБ | 1 с / 2–3 с |
| 12 ГБ | `qwen3.5:9b`, `gemma4:12b` | 5.5 / 7.3 ГБ | 1–2 с |
| 16 ГБ и больше | `gemma4:26b-a4b` — MoE, 4B активных | ~15.4 ГБ | 1–2 с |

MoE в последней строке не опечатка: в памяти лежат все 26 миллиардов, а на
каждый токен работают четыре. Поэтому она отвечает со скоростью маленькой
модели, а разговаривает как большая — для голосового робота это лучшая сделка
из существующих, если видеопамять позволяет.

**Русский язык.** Есть отдельная ветка, где русский родной, а не доля общего
корпуса: `GigaChat3-10B-A1.8B` от Сбера (MIT, MoE, 1.8B активных, GGUF лежит
на HuggingFace у `ai-sage`). По-русски она говорит естественнее ровесников и
при этом быстрая. Плата — вызов инструментов у неё проверен хуже: если робот
начнёт рассказывать о поездках вместо поездок, возвращайтесь на Qwen.

**Размышления.** Все свежие модели гибридные: сначала пишут ход мысли, потом
ответ. Роботу это разорительно — предел ответа у него 384 токена, и думающая
модель выбирает его целиком на рассуждения, обрывая фразу на полуслове. Мост
выключает размышления сам (`chat_template_kwargs`), но если модель их всё
равно пишет — в логе будет сказано, и лечится это нерассуждающим выпуском
модели (`-instruct`). Его и ставит `start.cmd`:
`qwen3:4b-instruct-2507-q4_K_M`.

**Окно контекста.** Умолчание Ollama — 4096 токенов, и робот в него не
помещается: один только системный промпт со схемами инструментов это около
семи тысяч. За краем Ollama молча срезает начало — вместе с промптом, где
записано, кто робот такой. Поэтому мост просит окно явно: 8192, а со сжатым
кэшем (`OLLAMA_KV_CACHE_TYPE=q8_0` вместе с `OLLAMA_FLASH_ATTENTION=1`) —
10240. Своё число — `--ctx`; больше ставить есть смысл, только если
видеопамяти с запасом: KV-кэш растёт вместе с окном.

**Скорость ответа: кэш один, и его берегут.** Ollama держит один кэш, и
быстрый ответ — это когда начало запроса (промпт и схемы, семь тысяч
токенов) уже лежит в нём: тогда читается только новая фраза, доли секунды.
Промах — секунды. Поэтому мост:

- шлёт роботу заголовки и знаки жизни (пинги) сразу, пока модель читает
  промпт, — робот не бросает ход через свои пять секунд (после поездки — не
  пингует: если ПК повис, робот должен сдаться и встать, как раньше);
- кладёт справку о собеседнике и дату со временем в последнюю реплику, а не
  перед схемами — смена говорящего больше не стирает кэш;
- не задаёт модели посторонних вопросов после ответа, а режиссёра сценок
  зовёт только в пустой комнате и не раньше двух минут после разговора;
- греет кэш настоящим началом запроса робота — при старте (оно хранится в
  `префикс.json` рядом со слепками голосов), после режиссёра и зрения, и по
  слову «Кузя» (`POST /warm`), пока человек договаривает фразу.

Попала ли фраза в кэш, видно в окне: на каждый запрос строка «модель:
прочитала N ток. за X с». Сотня-другая токенов — попала, семь тысяч — нет.

Модель распознавания занимает память отдельно и немного: `small` — около
гигабайта, `medium` — два. Начинать стоит со `small`: она уже заметно точнее
всего, что когда-то помещалось в робота.

Если CUDA не поднимется, `kuzya_pc.py` честно скажет об этом в лог и
перейдёт на процессор. Даже так настольная машина быстрее робота.

## Ограничения, о которых стоит знать

Сервер слушает всю домашнюю сеть (`--host 0.0.0.0`) и никого не спрашивает
пароль. В домашней сети это нормально, в общежитии или коворкинге — нет:
там запускайте с `--host 127.0.0.1` и пробрасывайте порт через ssh.

Маленькая модель может сдуру вызвать движение. Запрет ехать без имени
(`ROBOT_MOTION_NEEDS_NAME=1`) от этого страхует, но пока идёт проверка
лучше держать робота на подставке.

## Проверка

```
python pc/selftest.py
```

Поднимает настоящий сервер, подставляет вместо Ollama заглушку и делает
запрос **настоящим** клиентом `anthropic` — тем же, что стоит на роботе.
Порядок событий в потоке жёсткий, и на его нарушение клиент отвечает
исключением посреди фразы; глазами это не проверить.

Страница аватара проверяется отдельно, в настоящем Chromium на заглушках
вместо Live2D (нужен Playwright, интернет не нужен):

```
python pc/page_selftest.py
```
