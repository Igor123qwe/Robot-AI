# Мост к Open-LLM-VTuber

Опциональная надстройка над `pc/kuzya_pc.py`: вместо своей Live2D-страницы
(`pc/avatar/`) экран показывает более живую модель через чужой открытый
проект [Open-LLM-VTuber](https://github.com/Open-LLM-VTuber/Open-LLM-VTuber)
(OLLV) — у него богаче библиотека движений и мимики.

**Что НЕ меняется.** Своё распознавание речи, дальномер, инструменты
движения, личные дела людей, музыка, таймеры — всё это остаётся нашим,
как было. OLLV получает только то, в чём он сильнее нас: как выглядит и
двигается тело персонажа, когда он озвучивает уже готовую фразу. Пока
`OLLV_URL` не задан, `kuzya_pc.py` работает ровно как раньше — ни своя
страница, ни сценарист (`face/scenes.py`) не тронуты.

## Как это работает

1. Робот просит `/tts` синтезировать фразу — тем же путём, что и всегда.
   `pc/ollv_bridge.py` запоминает текст, эмоцию и ТОТ ЖЕ звук, что уже
   ушёл в динамик робота (второй раз не синтезируем).
2. Мост шлёт в OLLV один короткий сигнал по WebSocket — их штатный
   `ai-speak-signal` («персонажу есть что сказать»): не пишет в память и
   историю разговора, придуман именно для таких случаев.
3. OLLV зовёт свою LLM — но вместо настоящей модели там подложен
   провайдер-заглушка (`robot_bridge_llm.py`): она не думает, а спрашивает
   у моста, что говорить, и просто пересказывает это с тегом эмоции вроде
   `[joy]` впереди — его вырежет и превратит в выражение их собственный
   код (`live2d_model.py`), без нашего участия.
4. Их TTS-провайдер (`robot_bridge_tts.py`) вместо синтеза заново
   забирает тот же WAV с моста — рот на экране идёт по настоящему звуку.

Всё это проверено «от и до» на голом Python — реальный HTTP-сервер
(`kuzya_pc.py`), реальные файлы `robot_bridge_llm.py`/`robot_bridge_tts.py`,
без единой заглушки, плюс рукопожатие WebSocket по протоколу (RFC 6455)
против настоящего сокета (`pc/selftest.py`, «мост к Open-LLM-VTuber»).
Единственное, что не проверить без Windows и настоящей модели, — как это
выглядит в самом Live2D: рендер их фронтенда мы отсюда не видим.

## Установка на ПК

1. Склонировать сам OLLV рядом (не внутрь Robot-AI):
   ```
   git clone https://github.com/Open-LLM-VTuber/Open-LLM-VTuber C:\Open-LLM-VTuber
   cd C:\Open-LLM-VTuber
   ```
2. Наложить патч из этой папки (добавляет два новых файла и правит пять
   существующих — только добавления, ничего не удаляет и не трогает
   существующие провайдеры):
   ```
   git apply C:\Robot-AI\pc\ollv_bridge\robot_bridge.patch
   ```
   Не приложился «как есть» (OLLV успел обновиться) — открой файл патча,
   там всего семь мест, перенеси руками по комментариям в файлах
   `robot_bridge_llm.py`/`robot_bridge_tts.py` (в них расписано, куда что
   класть) и по образцу соседних провайдеров (`ollama_llm.py`, `piper_tts.py`)
   в затронутых factory- и config-файлах.
3. Поставить зависимости и фронтенд — по их собственному Quick Start:
   https://open-llm-vtuber.github.io/docs/quick-start
   (нужен `uv`, Python 3.10–3.12, Node.js для сборки фронтенда).
4. В `characters/<твой-персонаж>.yaml` (или в `conf.yaml`, если работаешь
   без отдельных персонажей) — переключить агента и синтез на мост:
   ```yaml
   agent_config:
     conversation_agent_choice: "basic_memory_agent"
     agent_settings:
       basic_memory_agent:
         llm_provider: "robot_bridge_llm"
   llm_configs:
     robot_bridge_llm:
       bridge_url: "http://127.0.0.1:4000"   # порт kuzya_pc.py, --port при запуске

   tts_config:
     tts_model: "robot_bridge_tts"
     robot_bridge_tts:
       bridge_url: "http://127.0.0.1:4000"
   ```
   Названия секций (`agent_config`, `llm_configs`, `tts_config`) — из их
   `config_templates/conf.default.yaml`; если структура успела измениться,
   ищи там, куда обычно вписывают `ollama_llm`/`piper_tts`, и вставляй по
   образцу.
5. Запустить OLLV (`uv run run_server.py` или как указано в их Quick Start)
   — с их же портом по умолчанию, 12393.
6. Запустить `kuzya_pc.py` с переменной окружения `OLLV_URL`, указывающей
   на их WebSocket:
   ```
   set OLLV_URL=127.0.0.1:12393/client-ws
   F:\robot-venv\Scripts\python.exe C:\Robot-AI\pc\kuzya_pc.py --model ... --port 4000
   ```
7. Направить съёмку экрана робота на страницу OLLV вместо своей: сейчас
   `Съёмка` в `kuzya_pc.py` снимает `http://127.0.0.1:<port>/avatar/`
   (наша страница) — поменяй адрес на страницу их фронтенда (обычно
   `http://127.0.0.1:12393/` в web-режиме, см. их Quick Start) в вызове
   `Съёмка(...)` в `main()`, если хочешь, чтобы на экране робота был
   именно OLLV, а не наш `pc/avatar/`.

## Известные ограничения (первая версия моста)

- Тег эмоции (`ЭМОЦИЯ_В_ТЕГ` в `pc/ollv_bridge.py`) переводит наши слова
  (рад/огорчён/…) в общеупотребимые английские имена (joy/sadness/…) —
  их модель ждёт ИМЕНА ИЗ СВОЕГО `model_dict.json`. Если у твоей модели
  выражения называются иначе, поправь словарь.
- Жесты руками, поиск ушедшего человека, поздравление с днём рождения и
  остальной сценарий (`face/scenes.py`) — рассчитаны на нашу страницу
  (`pc/avatar/`) и на её систему параметров. У OLLV своя, гораздо более
  простая модель поведения (только `[emotion]`-теги), и всё это в мост
  пока не перенесено — только эмоция и звук.
- Мост не проверялся против настоящего фронтенда OLLV (нет доступа к
  Windows с GPU и живой Live2D-моделью в этой среде) — первое включение
  стоит сделать под присмотром и быть готовым откатиться, убрав `OLLV_URL`.
