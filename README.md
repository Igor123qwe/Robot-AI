# Robot-AI

Домашний робот-ассистент на шасси WHEELTEC WD550 + D-Robotics RDK X5.
Голос, зрение, автономная езда по квартире, лицо на экране.

## Что в репозитории

```
web/          веб-пульт управления (открывается с телефона)
voice/        голосовой пайплайн: микрофон → STT → Claude → TTS
systemd/      юниты автозапуска
scripts/      установка и обновление на роботе
docs/         железо, сеть, дорожная карта
```

## Быстрый старт на роботе

Один раз:

```
git clone https://github.com/Igor123qwe/Robot-AI.git ~/Robot-AI
```

Дальше:

```
cd ~/Robot-AI
```

```
bash scripts/install.sh
```

## Обновление

Три способа, от ручного к автоматическому.

**На роботе руками:**

```
bash ~/Robot-AI/scripts/update.sh
```

**С ПК одной кнопкой** — двойной клик по `scripts\deploy.cmd` в папке репозитория
на компьютере. Он делает `git push` и сразу дёргает `update.sh` на роботе по SSH.
Адрес робота меняется переменной `ROBOT_HOST`.

**Само, каждые две минуты** — включить таймер на роботе:

```
sudo systemctl enable --now robot-autopull.timer
```

Тогда достаточно `git push` с ПК, робот подтянет сам. Проверить:
`systemctl list-timers robot-autopull` и `journalctl -u robot-autopull -n 20`.

Что перезапускается: только затронутое. Правка в `web/` — статика подхватывается
сама, но `web/server.py` требует перезапуска. Правка в `voice/` — `robot-voice`.
Шасси и rosbridge трогаются, только если поменялся их юнит.

**На ходу обновление не идёт.** Голосовой сервис держит файл `/run/robot-ai/moving`,
пока робот движется — по голосовой команде или с веб-пульта, неважно: признак
ставится по самому `/cmd_vel`. Скрипт обновления это видит и молча откладывает
до следующего срабатывания таймера. Признак старше минуты игнорируется — значит
сервис убили посреди поездки, и ждать больше нечего.

Продавить вручную, если очень надо:

```
bash ~/Robot-AI/scripts/update.sh --force
```

## Секреты

Ключи и пароли — в файле `~/.robot-ai.env` (вне репозитория, в `.gitignore`).
Шаблон: `.env.example`. Скопировать и заполнить:

```
cp ~/Robot-AI/.env.example ~/.robot-ai.env
```

```
nano ~/.robot-ai.env
```

## Веб-пульт

После `install.sh` доступен на `http://<ip-робота>:8000/pult.html`
(сейчас `http://192.168.0.50:8000/pult.html`).

- левый джойстик — ход во все стороны (меканум, 360°)
- правый — разворот на месте
- ползунок — предел скорости 0.05–0.80 м/с
- **СТОП** — аварийная остановка, она же пробел на клавиатуре
- индикатор батареи по `/PowerVoltage`
- видео с телефона (IP Webcam) — идёт **через робота**, а не напрямую

Кнопка «СТОП» нужна не для красоты: пока робот произносит «Еду вперёд метр»,
микрофон заглушён (своего эхоподавления нет), и голосовое «стоп» в эти
две-три секунды он не услышит. Пульт публикует в `/cmd_vel` напрямую и
работает всегда.

Пульт шлёт команды, **только когда джойстики заняты**. Раньше он слал нули
пятнадцать раз в секунду круглосуточно, и голосовая команда ехала рывками:
две струи команд в один топик. Закрыть вкладку было нельзя — она же динамик.

### Почему видео через робота

Телефон живёт в сети Huawei (`192.168.3.x`), ПК — в сети Ростелекома
(`192.168.0.x`), и напрямую браузер до телефона не достучится: двойной NAT.
Робот сидит в обеих сетях сразу, поэтому `web/server.py` забирает поток и
раздаёт его сам:

| Адрес | Что отдаёт |
|---|---|
| `/camera` | MJPEG-поток |
| `/camera/snapshot` | один кадр JPEG |
| `/camera/status` | JSON: доступен ли телефон |
| `/speak/events` | SSE: робот сказал новую реплику |
| `/speak/<id>.wav` | сама реплика |

Адрес телефона — в `ROBOT_PHONE_URL`, разово переопределяется параметром:
`/camera?src=192.168.3.9:8080`. В поле пульта можно вписать и прямой адрес
телефона — тогда браузер пойдёт к нему сам, минуя робота.

В `src` принимаются только домашние адреса (`192.168.*`, `10.*`, `172.16–31.*`)
и не принимается локалхост. Иначе это готовый прокси: робот стоит сразу в двух
сетях и по чужой просьбе сходил бы куда угодно, включая интернет.

### Динамик

Своего громкоговорителя у робота пока нет, а IP Webcam умеет только отдавать
звук, но не принимать. Поэтому говорит браузер: голосовой пайплайн кладёт
готовый WAV в `POST /speak` (принимается только с самого робота), пульт узнаёт
об этом по SSE и проигрывает.

Нажми **🔇** в шапке — браузеры не дают запускать звук без действия
пользователя. Текст реплики показывается субтитрами в любом случае, даже с
выключенным звуком.

Выбор запоминается: после перезагрузки страницы кнопка показывает **🔈** и
звук включается от первого же касания. И робот теперь знает, слышит ли его
хоть одна вкладка на самом деле, — раньше он считал слушателем любую открытую
страницу и молча «говорил» в немой браузер.

Когда приедет SOTAMIA — переключить `ROBOT_AUDIO_OUT=local`, и синтез пойдёт
сразу в `aplay`, потоком по предложениям. Ничего больше менять не придётся.

### Музыка

Играет та же вкладка, что и голос, но отдельным проигрывателем: реплики
кончаются, музыка — нет. Источников два.

**Интернет-радио** — по умолчанию, без ключей и без подписки. Каталог
[radio-browser.info](https://www.radio-browser.info/), тысячи станций, поиск
по названию («включи Рекорд») и по жанру («включи джаз»). Просим у каталога
только `codec=MP3`: AAC+ Chrome тянет через раз, а Firefox не тянет вовсе — на
этом уже потерян вечер.

**Яндекс.Музыка** — если задан `YANDEX_MUSIC_TOKEN`. Умеет то, чего радио не
умеет в принципе: конкретного исполнителя, конкретную песню, «Мою волну».
Нужна активная подписка Плюс — без неё Яндекс отдаёт тридцать секунд от
трека. Вход разовый, паролем нигде не светим:

```
pip3 install --user yandex-music
python3 voice/yandex_auth.py
sudo systemctl restart robot-voice
```

Скрипт покажет код и адрес страницы Яндекса, дождётся подтверждения и запишет
токен в `~/.robot-ai.env` — на экран токен не печатается и в историю команд не
попадает.

Библиотека `yandex-music` неофициальная: своего API Яндекс не публиковал.
Поэтому радио никуда не убирается — если Яндекс промолчал, играет оно. То же
и с токеном: он долгоживущий, но не вечный, и «Яндекс.Музыка не пустила» в
логе означает просто «запусти `yandex_auth.py` ещё раз».

Ссылки Яндекса подписанные и живут минуты, поэтому очередь треков держит
робот, а не пульт: пульт получает по одной песне и сообщает `POST
/music/ended`, когда она кончилась. Ошибка проигрывания считается тем же
самым — битая ссылка не должна останавливать вечер.

| Адрес | Кто зовёт | Что делает |
|---|---|---|
| `POST /speak/radio` | робот | бесконечный поток; пустое тело — выключить всё |
| `POST /speak/track` | робот | одна песня: `{"адрес": …, "название": …}` |
| `POST /speak/volume` | робот | громкость музыки, 0–1 |
| `POST /music/ended` | пульт | песня кончилась или не пошла |
| `GET /music/state` | робот | сколько песен доиграно |

### Микрофон под музыку

Кнопка **🎧** в шапке. Включена — эхоподавление браузера выключено.

Это не мелочь и не вкусовщина. Эхоподавление придумано против колонок: оно
берёт то, что играет система, и вычитает из микрофона. Пока играет музыка,
оно работает непрерывно — и глушит заодно живой голос, потому что отличить
остаток эха от «человек говорит поверх» ему нечем. На живом роботе это
выглядело так: включили музыку — уверенность распознавания упала с −0.25 до
−0.75, половина фраз вернулась пустыми, «Кузя» превратился в «Кульзу». И всё
это в наушниках, где эха физически не существует.

Если звук идёт из колонок — выключи кнопку, там эхо настоящее.

Заодно музыка приглушается сама, как только человек заговорил, и возвращается
через две секунды тишины. И робот, включая музыку, предупреждает свой
детектор речи: под ровный музыкальный фон он поднимает порог, иначе каждая
пауза уезжает в распознавание отдельным куском и возвращается пустой.
