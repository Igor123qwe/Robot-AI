# Robot-AI

Домашний робот-ассистент на шасси WHEELTEC WD550 + D-Robotics RDK X5.
Голос, зрение, автономная езда по квартире, лицо на экране.

## Что в репозитории

```
web/          веб-пульт управления (открывается с телефона)
voice/        голосовой пайплайн: микрофон → STT → Claude → TTS
systemd/      юниты автозапуска
scripts/      установка и обновление на роботе
docs/         железо, сеть, дорожная карта
```

## Быстрый старт на роботе

Один раз:

```
git clone https://github.com/Igor123qwe/Robot-AI.git ~/Robot-AI
```

Дальше:

```
cd ~/Robot-AI
```

```
bash scripts/install.sh
```

## Обновление

Три способа, от ручного к автоматическому.

**На роботе руками:**

```
bash ~/Robot-AI/scripts/update.sh
```

**С ПК одной кнопкой** — двойной клик по `scripts\deploy.cmd` в папке репозитория
на компьютере. Он делает `git push` и сразу дёргает `update.sh` на роботе по SSH.
Адрес робота меняется переменной `ROBOT_HOST`.

**Само, каждые две минуты** — включить таймер на роботе:

```
sudo systemctl enable --now robot-autopull.timer
```

Тогда достаточно `git push` с ПК, робот подтянет сам. Проверить:
`systemctl list-timers robot-autopull` и `journalctl -u robot-autopull -n 20`.

Что перезапускается: только затронутое. Правка в `web/` — статика подхватывается
сама, но `web/server.py` требует перезапуска. Правка в `voice/` — `robot-voice`.
Шасси и rosbridge трогаются, только если поменялся их юнит.

**На ходу обновление не идёт.** Голосовой сервис держит файл `/run/robot-ai/moving`,
пока робот движется — по голосовой команде или с веб-пульта, неважно: признак
ставится по самому `/cmd_vel`. Скрипт обновления это видит и молча откладывает
до следующего срабатывания таймера. Признак старше минуты игнорируется — значит
сервис убили посреди поездки, и ждать больше нечего.

Продавить вручную, если очень надо:

```
bash ~/Robot-AI/scripts/update.sh --force
```

## Секреты

Ключи и пароли — в файле `~/.robot-ai.env` (вне репозитория, в `.gitignore`).
Шаблон: `.env.example`. Скопировать и заполнить:

```
cp ~/Robot-AI/.env.example ~/.robot-ai.env
```

```
nano ~/.robot-ai.env
```

## Веб-пульт

После `install.sh` доступен на `http://<ip-робота>:8000/pult.html`
(сейчас `http://192.168.0.50:8000/pult.html`).

- левый джойстик — ход во все стороны (меканум, 360°)
- правый — разворот на месте
- ползунок — предел скорости 0.05–0.80 м/с
- индикатор батареи по `/PowerVoltage`
- видео с телефона (IP Webcam) — идёт **через робота**, а не напрямую

### Почему видео через робота

Телефон живёт в сети Huawei (`192.168.3.x`), ПК — в сети Ростелекома
(`192.168.0.x`), и напрямую браузер до телефона не достучится: двойной NAT.
Робот сидит в обеих сетях сразу, поэтому `web/server.py` забирает поток и
раздаёт его сам:

| Адрес | Что отдаёт |
|---|---|
| `/camera` | MJPEG-поток |
| `/camera/snapshot` | один кадр JPEG |
| `/camera/status` | JSON: доступен ли телефон |
| `/speak/events` | SSE: робот сказал новую реплику |
| `/speak/<id>.wav` | сама реплика |

Адрес телефона — в `ROBOT_PHONE_URL`, разово переопределяется параметром:
`/camera?src=192.168.3.9:8080`. В поле пульта можно вписать и прямой адрес
телефона — тогда браузер пойдёт к нему сам, минуя робота.

### Динамик

Своего громкоговорителя у робота пока нет, а IP Webcam умеет только отдавать
звук, но не принимать. Поэтому говорит браузер: голосовой пайплайн кладёт
готовый WAV в `POST /speak` (принимается только с самого робота), пульт узнаёт
об этом по SSE и проигрывает.

Нажми **🔇** в шапке — браузеры не дают запускать звук без действия
пользователя. Текст реплики показывается субтитрами в любом случае, даже с
выключенным звуком.

Когда приедет SOTAMIA — переключить `ROBOT_AUDIO_OUT=local`, и синтез пойдёт
сразу в `aplay`, потоком по предложениям. Ничего больше менять не придётся.
