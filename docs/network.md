# Сеть

История с сетью съела вечер. Здесь — что было сломано, что сделано и как
диагностировать, если связь опять пропадёт.

## Что было сломано

1. **`apstart1.sh`** (SysV-скрипт в `/etc/init.d/`) при каждой загрузке запускал
   `~/apstart.sh`, который поднимал точку доступа на `wlan0` с адресом
   `192.168.0.100` и стартовал `isc-dhcp-server`. Домашняя сеть тоже
   `192.168.0.x` → маршрут через `wlan0` перебивал `eth0`, весь локальный
   трафик уходил в никуда.

   Решено:
   ```
   sudo chmod -x /etc/init.d/apstart1.sh
   sudo systemctl mask apstart1
   sudo systemctl disable isc-dhcp-server
   ```
   (`scripts/install.sh` делает это сам.)

2. **Три интерфейса с одним адресом** — `eth0`, `wlan0`, `usb0` конкурировали.

3. **Утилита `~/RDK_X5_NET/main.py`** (меню управления Wi-Fi/AP от WHEELTEC) —
   **не запускать по SSH**: она перестраивает интерфейсы и обрывает саму себя.
   Только с монитором.

## Текущая конфигурация

- **Ethernet:** статика `192.168.0.50/24`, шлюз `192.168.0.1`,
  профиль NetworkManager «Ethernet connection 2», autoconnect yes
- **Wi-Fi:** `wpa_supplicant@wlan0` с конфигом
  `/etc/wpa_supplicant/wpa_supplicant-wlan0.conf`, включён в автозапуск.
  Подключается к сети `Kr_1`

### Двойной NAT — нерешённое

Дома два роутера:
- основной Ростелеком RT-GM-3 → `192.168.0.x` (ПК на проводе)
- второй Huawei WiFi AX2 (SSID `Kr_1`) → раздаёт свою подсеть `192.168.3.x`

Робот по Wi-Fi попадает в `192.168.3.x` и **невидим с ПК** из `192.168.0.x`.

Что сделать: перевести Huawei в режим точки доступа (через приложение AI Life) —
тогда все окажутся в одной сети.

Ещё: `dhclient wlan0` после ребута сам не запускается, адрес по Wi-Fi может не
подняться. Проверить и при нужде добавить сервис.

## Диагностика с Windows

Просканировать подсеть:

```powershell
$p = 1..254 | %{ (New-Object Net.NetworkInformation.Ping).SendPingAsync("192.168.0.$_",1000) }
foreach($r in $p){ if($r.Result.Status -eq 'Success'){ "$($r.Result.Address)" } }
```

Найти по MAC:

```powershell
arp -a | findstr c6-aa
```

MAC платы: `eth0` = `c6:aa:e3:4b:78:0e`, `wlan0` = `18:ce:df:79:73:df`.

Запасной канал — IPv6 link-local:

```
ssh wheeltec@fe80::c4aa:e3ff:fe4b:780e%16
```

где `%16` — номер интерфейса Ethernet на ПК, смотреть через `Get-NetIPAddress`.

## Если связь внезапно пропала

1. **VPN Outline на ПК.** Его виртуальный адаптер `outline-tap0` перехватывал
   локальный трафик. Отключён через `Disable-NetAdapter`. Проверять первым делом.
2. Не запускался ли `~/RDK_X5_NET/main.py` по SSH.
3. Не вернулся ли `apstart1` (проверить `systemctl is-enabled apstart1`).
