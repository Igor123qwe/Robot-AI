# Сайт услуг по сопровождению маркетплейсов

Статический сайт на Astro 5 с контентным движком: pillar-разделы, пять шаблонов
статей, автоперелинковка по сущностям, генерация `llms.txt`, Schema.org, три
калькулятора и приём заявок в Telegram.

Реализация ТЗ версии 1.0 от 15.08.2026. Ссылки вида «§5.3» в коде и ниже —
разделы этого ТЗ.

---

## Быстрый старт

```bash
cd site
npm install
npm run dev            # http://localhost:4321
```

Сборка и проверка:

```bash
npm run build          # валидация контента + сборка + проверки готового dist
npm run preview        # посмотреть собранный сайт
```

Сборка **падает**, если контент нарушает правила §7.3 — это задумано.

## Как добавить статью

1. Создайте файл `src/content/baza/<slug>.mdx`. Имя файла может быть любым,
   адрес страницы берётся из поля `slug`.
2. Заполните frontmatter (полный набор полей — §7.1 ТЗ):

```yaml
---
title: "Маркировка тормозных колодок: сроки и коды"   # до 65 символов, лучше до 60
h1: "Маркировка тормозных колодок"                     # необязательно, по умолчанию = title
description: "Когда началась обязательная маркировка…" # 120–170 символов, лучше 140–160
slug: "markirovka-tormoznyh-kolodok"                   # латиница, цифры, дефис
pillar: "chestnyj-znak"                                # один из разделов site.config.mjs
type: "reference"                    # article | howto | reference | troubleshoot | comparison
direct_answer: "Маркировка тормозных колодок…"         # 30–90 слов, самодостаточный ответ
related_service: "markirovka-chestnyj-znak"            # какая услуга покажется в статье
tags: ["маркировка", "автозапчасти"]
entities: ["Честный Знак", "ТН ВЭД 8708 30"]           # для автоперелинковки и Schema
takeaways:                                             # блок «Коротко», 3–5 пунктов
  - "Первый ключевой факт."
  - "Второй ключевой факт."
  - "Третий ключевой факт."
faq:
  - q: "Вопрос?"
    a: "Ответ."
published: 2026-08-15
updated: 2026-08-15
---
```

3. Напишите текст. Требования к телу статьи (§5.3):
   - минимум 2 500 знаков и хотя бы один `##`;
   - каждый `##` — вопрос или конкретное утверждение, а не абстрактное слово;
   - первый абзац под каждым `##` содержит законченный ответ;
   - факты — в таблицах, а не в прозе;
   - абзац не начинается с местоимения («Это», «Он», «Они»).

4. Проверьте и соберите:

```bash
npm run validate    # быстрая проверка без сборки, показывает файл и строку
npm run build
```

### Дополнительные поля по типам статей

| Тип | Обязательное поле | Что даёт |
|---|---|---|
| `howto` | `steps: [{name, text}]` | разметка HowTo и нумерованные шаги |
| `troubleshoot` | `faq` минимум с двумя вопросами | разметка FAQPage |
| `reference` | — | разметка Dataset автоматически |
| любой | `own_data` + `has_own_data: true` | выделенный блок собственных данных и Dataset |
| регуляторный | `changelog: [{date, text}]` | блок «Что изменилось» (§5.5) |

### Врезки в тексте

Пишутся обычным Markdown, компоненты импортировать не нужно:

```markdown
:::warning[Свой заголовок]
Текст предупреждения.
:::
```

Доступны: `warning`, `note`, `example`, `own-data`, `actual`.

### Черновики и демо-контент

Поле `demo: true` показывает над статьёй предупреждение и закрывает страницу
от индексации — она не попадёт ни в карту сайта, ни в `llms.txt`. Так помечен
демонстрационный кейс `src/content/kejsy/primer-kejsa-markirovka.mdx`.

## Правила, из-за которых падает сборка (§7.3)

| Правило | Где проверяется |
|---|---|
| Нет `direct_answer` либо он короче 30 / длиннее 90 слов | `validate-content.mjs`, схема коллекции |
| `title` длиннее 65 символов | оба |
| `description` вне 120–170 символов | оба |
| Статья короче 2 500 знаков | `validate-content.mjs` |
| Нет ни одного H2 | `validate-content.mjs` |
| Битая внутренняя ссылка | `validate-content.mjs` и проверка готового `dist` |
| Изображение без `alt` | оба |
| Дублируется `slug` или `title` | оба |
| Ссылка без завершающего слеша | оба |
| Нет блока прямого ответа в HTML | проверка `dist` |

Отдельно проверяется готовая сборка: один H1 на странице, canonical,
`lang="ru"`, JSON-LD, наличие `robots.txt`, `llms.txt`, `llms-full.txt`
и карт сайта, доступ краулеров в `robots.txt`.

Проверить, что правило действительно работает, можно так: временно сломайте
одно поле и запустите `npm run validate` — в отчёте появится файл и строка.

## Как обновить ставки комиссий

Все ставки — в `src/data/commissions.json`, код калькуляторов их не содержит.

1. Откройте файл, поправьте значения в `categories`, `logistics`, `lastMile`,
   `acquiring`, `storagePerLiterPerDay`.
2. Обновите `updated` и `source`.
3. Поставьте `"verified": true` — пока стоит `false`, на страницах
   калькуляторов висит предупреждение о непроверенных ставках.
4. `npm run build`.

Справочник товарных групп маркировки правится так же — `src/data/markirovka.json`.

> Значения в репозитории — стартовые. Перед публикацией сверьте их
> с актуальными тарифами площадок и с постановлениями по товарным группам.

## Как задеплоить

### Первая настройка сервера

1. Поставьте Node 20+, nginx и получите сертификат.
2. Скопируйте `deploy/nginx.conf`, замените `example.ru` на домен,
   проверьте `nginx -t`, перезагрузите nginx.
3. Заполните `/etc/marketplace-site.env` по образцу `.env.example`
   (как минимум `TELEGRAM_BOT_TOKEN` и `TELEGRAM_CHAT_ID`).
4. Установите обработчик форм:

```bash
cp deploy/forms.service /etc/systemd/system/site-forms.service
systemctl daemon-reload && systemctl enable --now site-forms
curl -s localhost:8787/healthz     # {"ok":true,"telegram":true}
```

### Выкладка

```bash
SSH_TARGET=user@example.ru ./deploy/deploy.sh
```

Скрипт валидирует контент, собирает сайт, синхронизирует `dist/` по rsync,
перезапускает обработчик форм и пингует IndexNow.

### Автодеплой по push в main

Шаблон workflow лежит в `deploy/github-actions.yml`. Скопируйте его
в `.github/workflows/site.yml` и заведите секреты `SSH_HOST`, `SSH_USER`,
`SSH_KEY`, `SITE_PATH`, `PUBLIC_DOMAIN`, `INDEXNOW_KEY`.

Важно: в CI нужен `fetch-depth: 0` — дата обновления статьи берётся
из истории коммитов файла (§5.5), а не из frontmatter.

## Что генерируется при сборке

| Файл | Чем создаётся | Зачем |
|---|---|---|
| `robots.txt` | `integrations/seo-artifacts.mjs` | явный доступ AI-краулерам (§5.1) |
| `llms.txt` | там же | карта сайта в Markdown для языковых моделей (§5.2) |
| `llms-full.txt` | там же | весь текст сайта одним файлом |
| `sitemap-index.xml` + карты по разделам | там же | индексация, `lastmod` из git |
| `<INDEXNOW_KEY>.txt` | там же | подтверждение владения доменом |
| `og/*.png` | `integrations/og-images.mjs` | картинки 1200×630 для соцсетей (§8.3) |

OG-картинки кэшируются в `.og-cache` по хэшу заголовка: при неизменном
заголовке не перерисовываются. Шрифт берётся из `assets/fonts/og-regular.ttf`
и `og-bold.ttf`, если их нет — из системных (DejaVu, Liberation).

## Автоперелинковка (§7.2)

При сборке первое вхождение сущности в тексте статьи превращается в ссылку.
Словарь строится из поля `entities` всех материалов, приоритет:
ручное переопределение → pillar → услуга → статья.

- не больше 8 автоссылок на статью;
- не больше одной ссылки на один и тот же адрес;
- ссылок на саму себя не ставится;
- заголовки, код и уже существующие ссылки не трогаются.

Чтобы жёстко закрепить сущность за адресом, добавьте её
в `src/data/entity-links.json`.

## Аналитика

Счётчик Яндекс.Метрики подключается через `PUBLIC_METRIKA_ID` и грузится
только после события `load`. Цели, которые отправляются сами:

| Цель | Когда |
|---|---|
| `form_submit` | успешная отправка любой формы |
| `cta_click` | клик по инлайн-CTA, карточке услуги, кнопке тарифа |
| `tg_click` | клик по любой ссылке на Telegram |
| `scroll_75` | прочитано 75% статьи |
| `calc_use` | использование калькулятора и отправка расчёта |

В Метрике эти цели нужно создать как «JavaScript-событие» с теми же
идентификаторами.

## Приёмка: что проверить руками

```bash
# Контент отдаётся краулерам целиком
curl -A "GPTBot" -s https://example.ru/baza/<slug>/ | grep -c "<h1"
curl -A "ClaudeBot" -s -o /dev/null -w "%{http_code}\n" https://example.ru/

# Служебные файлы
curl -s https://example.ru/llms.txt | head
curl -s -I https://example.ru/robots.txt

# Редиректы
curl -s -o /dev/null -w "%{http_code} %{redirect_url}\n" https://example.ru/tarify
curl -s -o /dev/null -w "%{http_code} %{redirect_url}\n" http://example.ru/
```

Проверено на этой сборке локально: Lighthouse mobile 100/100/100/100
на главной, странице услуги, статье, калькуляторе и тарифах; LCP 1.1–1.2 с,
CLS 0, внешних JS-файлов нет. На боевом домене показатели зависят
от хостинга — TTFB из Москвы и Санкт-Петербурга нужно измерить отдельно.

Дополнительно на боевом домене: валидация Schema в Rich Results Test
и в валидаторе Яндекса, подключение Вебмастера и Метрики, проверка,
что WAF хостинга не режет AI-краулеров по User-Agent.

## Ограничения текущей поставки

- Тексты услуг, кейсов и статей — демонстрационные: показывают работу шаблонов
  и структуру, но требуют замены на реальные материалы заказчика.
- Ставки комиссий и справочник товарных групп не сверены с первоисточниками
  (`verified: false`), на страницах об этом предупреждение.
- Политика обработки персональных данных — заглушка под текст заказчика (§11),
  страница закрыта от индексации.
- Реквизиты, ИНН, контакты и имя автора — плейсхолдеры из `site.config.mjs`.
